# A development skill pack on top of the memory

Status: written before the code, issue #111.

## Problem

Omoikane is a memory template only.
A system built from it starts with seven memory skills (`/ingest`, `/distill`, `/ask`, `/lint`, `/prune`, `/synthesize`, `/wrap-up`) and nothing for the work itself.
On 2026-10-07 the user widened the objective: Omoikane becomes a work toolkit, and a system that builds software gets a set of development skills on top of the memory (`omoikane/raw/inbox/2026-10-07-omoikane-becomes-a-toolkit.md`).
A research-only system keeps what it has today.

## The objective, restated

Every new system starts from the template.
Its agents keep the wiki on their own, from what the user states while building, domain knowledge included; that part does not change.
A system that builds software also starts with a pack of development skills, so the first session can design, plan, review, test, secure and ship without the user installing anything.

What follows from it:

- `omoikane/wiki/domain/omoikane-objective.md`, `omoikane/wiki/decisions/objective-criterion-stays-out-of-agents-md.md`, the opening of `docs/architecture.md`, the opening of `README.md` and the opening of `AGENTS.md` describe the memory-only objective; each gets the toolkit added. The wiki pages change through `/wrap-up`, from the inbox note above, not by hand.
- pstack becomes a reference in its own right (`omoikane/raw/inbox/2026-10-06-pstack-is-a-reference.md`).
- The verdicts in `omoikane/raw/inbox/2026-10-06-pstack-skills-review.md` that rejected a skill for "no memory link" are reopened for the pack; the verdicts about memory gaps stand.

## Layout

The pack is a set of ordinary skill folders under `.claude/skills/`, next to the seven memory skills.

- One copy only. The template ships the pack in `.claude/skills/`, and the template's own development uses it (dogfooding, chosen by the user).
- `omoikane/packs/dev.md` is the manifest: one table row per pack skill with its source, commit, licence and every change made to the upstream text. `new-system.py`, `context-budget.py` and the tests read the skill names from it.
- A vendored skill keeps its upstream `LICENSE` in its own folder.

Harness discovery, checked 2026-10-07:

| Harness | Reads | Change needed |
|---|---|---|
| Claude Code | `.claude/skills/<name>/SKILL.md` | none |
| OpenCode | `.opencode/skills/`, `.claude/skills/`, `.agents/skills/` (opencode.ai/docs/skills) | none; it reads `.claude/skills/` already |
| Pi | `.pi/skills/`, `.agents/skills/`, plus paths in `.pi/settings.json` `skills`, resolved from `.pi/` (`docs/skills.md`, `docs/settings.md` of `@earendil-works/pi-coding-agent` 1.0.4) | add `.pi/settings.json` with `"skills": ["../.claude/skills"]`; Pi then gets the memory skills too |

Rejected: a copy per harness (`.agents/skills/` beside `.claude/skills/`). OpenCode reads both folders and would load every skill twice.
Rejected: the pack in `omoikane/packs/dev/skills/`, copied into `.claude/skills/` on demand. The template's dogfood copy would drift from the source copy, and a check would be needed to keep them equal.

## Opting in

`python omoikane/bin/new-system.py --pack dev` keeps the pack; without `--pack dev` it deletes the folders the manifest lists, so a research-only system has the seven memory skills and the budget it has today.
`new-system.py` already removes what the template holds for itself, so removing the pack fits the same run, and `git restore .` still undoes it.

Known gap: a clone used for research without running `new-system.py` carries the pack.
The `README.md` setup section says to run it in both uses.

## Context budget

Every skill description loads at session start in Claude Code and Pi, and OpenCode has no way to hide one.
The user chose every pack skill model-invocable (no `disable-model-invocation`).

- `context-budget.py` measures two parts instead of one: `skill frontmatter` (the memory skills, limit 600 as today) and `dev pack frontmatter` (the skills the manifest lists, limit set from the ported descriptions, first estimate 2,000).
- A research-only system measures 0 for the pack part, so it passes as today.
- The `total` limit rises by the pack limit only.
- Descriptions are rewritten to state the trigger in one sentence where the upstream text is longer; the upstream text stays in the body.

Principles: the 24 pstack principles as 24 skills would cost roughly 1,600 tokens of descriptions.
Chosen by the user: one `principles` skill whose description lists the triggers and whose `references/` hold one file per principle, read on demand, as `poteto-mode` indexes them.
The cost accepted: a trigger matched by a router is less precise than one matched by its own description.

## Cloudflare validators on Windows

`readFileWithinLimit` in `validate-findings.cjs` (lines 604-613), and its copy in `validate-coverage-ledger.cjs`, open the input with `O_NOFOLLOW | O_NONBLOCK` and refuse to run when Node does not define them.
Node on Windows defines neither, so both validators exit with `OS no-follow and nonblocking input protection is unavailable`.
Linux, macOS and WSL are not affected.

Fallback, on `win32` only:

1. `lstat` with `bigint: true`; refuse a symbolic link or junction, require a regular file.
2. `open` with `O_RDONLY`.
3. `fstat` with `bigint: true` on the descriptor; refuse when `dev` or `ino` differ from step 1, which closes the swap between check and open.

`O_NONBLOCK` has no counterpart to add: Windows named pipes live under `\\.\pipe\`, not on the file system.
The POSIX path stays as it is.
The upstream test suites must pass on Windows and Linux.
The patched copy is listed in `omoikane/packs/dev.md`, and the same change is offered upstream as a pull request; once merged, the copy returns to upstream as it is.

`SKILL.md` also describes the parent's artifact promotion in POSIX terms (no-follow descriptors, link count of 1). Check whether it needs a Windows step before the pack ships.

# Wrap up a period of work

Task: at the end of a working day, bring the wiki up to date with what happened since the last wrap-up. The human runs this instead of, or besides, the scheduled run of `omoikane/bin/wiki-ingest.ps1`. Done means: every file in the inbox processed, the commits of the period read for what no session covered, `/synthesize` run when due, `omoikane/log.md` appended, `wiki-lint.py` clean.

Argument: how many days to look back. With none, the period starts at the date of the last `## [YYYY-MM-DD] wrap-up |` heading in `omoikane/log.md`; with no such heading, one day.

Steps:

1. Run `python omoikane/bin/review-removals.py`, so bullets the human deleted from `omoikane/_review.md` are not filed again.
2. List `omoikane/raw/inbox/` and `omoikane/raw/inbox/sessions/`. The inbox is a queue: process every file in it, whatever its date, since a file left there was never processed. Give each file to its own subagent when your harness has them, one at a time, never two at once: every operation appends to `log.md` and `_review.md`. The subagent reads `omoikane/prompts/distill.md` for a file under `sessions/`, `omoikane/prompts/ingest.md` for any other, follows it with the file as argument, and returns the prompt's report. Without subagents, run the prompts yourself, one file after another. The capture of this session may be among them: distill it like the others; the next capture of this session starts after the turns already distilled.
3. Read the commits of the period: `git log --branches --no-merges --since=<period start> --format="%h %ad %an%n%s%n%b" --date=iso -- . ":(exclude)omoikane"`. A commit made during a captured session (its time between that session's `started` and `ended`, on its `branch`) is that session's; skip it unless its body states a reason the session page does not have. For each remaining commit, judge the subject and body by the rules of `omoikane/prompts/distill.md` ("What is worth a page" and the five rejection rules): a body that gives the reason for a choice is a `decision`, a root cause found the hard way is a `gotcha`, a rule the system must follow is a `domain` page. Open the diff (`git show --stat <sha>`, then the files) only to confirm a claim, never to invent one the message does not make. When at least one commit yields a page, write one source page `omoikane/wiki/sources/commits-<period start>-to-<today>.md` with the page contract, `type: source`, `dated` set to the newest commit's date, listing each commit used (`<sha> <subject>`), and cite it from every page those commits fed. Route guards, prompt fixes and todos to `omoikane/_review.md` as distill step 6 does, under `## [YYYY-MM-DD] wrap-up | commits`.
4. Run `python omoikane/bin/synthesize-due.py`. Exit code 0: follow `omoikane/prompts/synthesize.md` with no argument.
5. Append to `omoikane/log.md`: `## [YYYY-MM-DD] wrap-up | <period start> to <today>`, then one line per file processed (`- distill <file>` or `- ingest <file>`), `- commits: <n> read, <n> used` with the pages created and updated, and `- synthesize` when it ran.
6. Run `python omoikane/bin/wiki-index.py` then `python omoikane/bin/wiki-lint.py`. Fix every finding.

Do not commit or push: the human reviews the changes and commits them. Report, in this order: the period covered, files processed with the pages each created or updated, commits used and the pages they fed, proposals and todos filed in `_review.md`, whether `/synthesize` ran, and the files you changed.
